# Incident Response Playbook

## Purpose
Guide teams through a repeatable response flow for operational incidents.

## When to use
- Active outage or severe degradation.
- Launch-blocking operational issue.
- Multi-workspace instability.

## Response Flow
1. Identify severity using the escalation matrix.
2. Assign incident commander and communication owner.
3. Stabilize service with workaround or rollback.
4. Communicate status updates on defined cadence.
5. Resolve root cause and validate recovery.
6. Run post-incident review and document actions.

## Communication Checklist
- [ ] Issue summary published
- [ ] Impact scope confirmed
- [ ] Next update time shared
- [ ] Recovery confirmation shared

## Evidence Checklist
- [ ] Timeline of incident
- [ ] Triggering event
- [ ] Logs/screenshots
- [ ] Mitigation applied
- [ ] Customer impact summary

## Post-Incident Review
- What happened?
- Why did it happen?
- What prevented faster resolution?
- Which safeguards must be added?
- Who owns follow-up actions?

## Expected Result
Faster stabilization, clear stakeholder communication, and reduced repeat incidents.
